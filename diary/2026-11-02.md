# 2026-11-02

## 18:02 — Rasters from the lake; first run in ArcGIS Pro 3.7 on Windows

### What changed
- 159f088 (2026-11-01): rasters (COGs) can be added to the map. `RasterLoader` asks
  `/api/map/assets/{id}/raster-access` for temporary lake credentials, checks that the lake can
  be reached, then `CloudRasterConnection` writes a `.acs` with them
  (`%LOCALAPPDATA%\GoBase\connections\<asset>_<expiry unix>_<6 hex>.acs`), and
  `LayerLoader.AddRasterAsync` adds the layer with pyramids and statistics turned off.
  `RasterCredentialRefresher` (started in `Module1.Initialize`) renews the credentials 10 min
  before they expire by pointing the layer at a new `.acs`. Needs GoBase-Web ADR-022.
- bc6c7ad, 9ccfb02: README build section. `dotnet build GoBase.csproj` also writes the
  `.esriAddinX`, on Windows too; Visual Studio is needed only for debugging.
- 733b2a7: README section "When the GoBase button does nothing".
- 238d7bd: a failed "Add to map" now writes the whole exception, with its stack, to the debug
  output (`GoBase: adding vector|raster <id> failed: ...`).

### Problems solved

  → clone with `-b feat/raster-access`.
- `dotnet build`: "specify which project or solution file" → the folder holds `GoBase.csproj`
  and `GoBase.slnx` → name one.
- No "Add-in package:" line on Windows → the terminal logger hides it; the file is built
  anyway (`-tl:off` shows the line).
- Pro: "blocked, source not trusted" → Add-In Manager → Options → Load all add-ins without
  restrictions.
- Tab appears, button does nothing; Pro log (Ctrl+Alt+M): `Type not found: GoBase.Module1`,
  `Module GoBase_Module failed to create` → Windows 11 Smart App Control blocked the unsigned
  `GoBase.dll` (the DLL was fine: the type is in it, built against 13.7.0.0) → turn Smart App
  Control off.
