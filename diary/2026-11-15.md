## "Add to map" works; vectors: streaming tried, GeoParquet download proposed

### What changed
- f4fe88e: "Object reference not set to an instance of an object" for every "Add to map", vectors
  and rasters. Cause, read in Pro's decompiled `execute_helper.eval_modal`: the
  `CancelableProgressor` overload of `Geoprocessing.ExecuteToolAsync` sets `progressor.Max`
  without a null check. Fix: the `CancellationToken` overload. Add-to-map failures now also go to
  `%LOCALAPPDATA%\GoBase\gobase.log` (`ErrorLog`); DebugView captured nothing.
- 7a23339: RASID branding removed. Logos deleted, "GoBase" as text in the panel header, generic
  add-in icon on the ribbon, Author/Company/copyright "GoBase", `Rasid*` style keys → `GoBase*`.
  The README still says where the add-in was forked from.
- Experimental commit: vector layers follow the map (`VectorViewRefresher`). 0.4 s after the map
  stops, each GoBase vector layer is fetched again for the view; a move cancels a fetch. Pages are
  written as they arrive (`FeatureWriter`, `Geodatabase.ApplyEdits`, outside an edit operation),
  1,000 features per MCT turn, and only that layer is invalidated. Feature classes are named
  `gobase_<asset id hex>_<geometry type>_<utc>`, so a layer's data source says what to fetch.

### Problems solved
- `MapView.Redraw` from the UI thread → `CalledOnWrongThreadException` → call it on the MCT.
- JSONToFeatures made a Z-enabled feature class; geometries without Z were refused → `FeatureWriter`
  writes Z (and M) when the feature class has them.
- Slow writes: GeoJSON → Esri JSON → `ImportFromJson` + `SimplifyAsFeature`, and a regex per
  property per feature. Geometry builders with ring orientation fixed by the shoelace sign, and a
  per-page property→field map: 10,000 features 5.7 s → 2.2 s (CoreHost harness).
- `Redraw(true)` cleared the whole map cache, basemap included → `MapView.Invalidate(layer, extent)`.
- `dotnet tool install -g ilspycmd` hung: ilspycmd 11.2 is a pointer package
  (`RuntimeIdentifierPackages`). `ilspycmd.any` from NuGet's flat container runs with `dotnet`.

### Findings: Pro 3.7 and GeoParquet
- Reads GeoParquet natively (ParquetFilePlugin, ogr_Parquet). Local file, 200,000 polygons, 17 MB:
  opens as a polygon feature class, EPSG:4326, in 4 s; one map view's features in 0.35 s; full read
  1.0 s; MakeFeatureLayer 1.0 s; ExportFeatures to a file geodatabase 6.4 s.
- Invalid `geo` metadata (a CRS that is not full PROJJSON) makes Pro report "does not exist";
  GDAL only warns `proj_create: Missing "type" key`. Leave `crs` out for WGS 84.
- Through an `.acs` (Overture's public bucket, Amazon provider, `AWS_NO_SIGN_REQUEST YES`): works,
  but opening a 49.6 MB file received 125 MB before answering; afterwards count, a view and a layer
  took 1–2 s with nothing more received. So Pro fetches the whole file, not the parts a view
  needs. This link runs at ~0.2 MB/s to us-west-2. The MinIO path-style variant (the plugin's
  lake settings) had not finished opening after 9 minutes.
